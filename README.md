## 使用

原生建造菜单 → **蘇清的返鲜冰箱**。无额外技能门槛。

| 建造输入 | 数量/处理 |
| --- | --- |
| 小金属板 | 4件，消耗 |
| 电线 | 2件，消耗 |
| 闹钟、电子表、怀表、经典指针腕表 | 每种1件，消耗四件不同实物 |
| 螺丝刀、焊接面罩 | 保留 |
| 焊枪 | 消耗1原生用量，保留工具本体 |

电子表接受原版6种左右手/颜色版本，经典腕表接受8种版本。暂停、取消和建造付款使用原生BuildLogic；无自定义重复扣料或额外返料路径。

使用市电或发电机。建成默认开启返鲜；右键可关闭/开启，关闭返鲜时仍按普通冰箱工作。只能处理**直接放入**的标准可腐坏Food；包中食物不处理。

## 沙盒

- `Enabled`：返鲜总开关，默认true。
- `Capacity`：**默认200，整数50–1000**，适用于新建及已加载的返鲜冰箱。调小不会删除物品，超过新容量后按原版规则限制继续放入。
- `RestoreHours`：恢复一个完整新鲜期所需游戏小时，默认10，0.25–1000。每小时净减少`食物原生新鲜期 / RestoreHours`的食物年龄，最低0。
- `AllowRotten`：默认true，允许逐步恢复仍存在的腐坏食物。

腐坏食品恢复期间需要保护其不被原生自动替换/删除。该保护只作用于这台冰箱的已开启、已通电且符合条件的直接食品；不改变腐坏阈值、生熟、毒素、污染、营养字段和吃剩份量。关闭原生自动删除时不改写临时年龄；有腐坏替换规则的食品会暂存并暂停该条规则，在处理后恢复，其他模组对年龄或替换规则的显式编辑予以保留。烧焦食品、受精蛋、没有标准保鲜期的食物不处理。已经被其他机制删除或替换的物品不会重建。

原版自动删除启用或其值未知时仍使用先前的年龄保护路径，本轮没有更改该分支，也没有宣称其在PZO跨帧节流下的显示与调度问题已一并解决。本次已核实的正式档使用 `DaysForRottenFoodRemoval=-1`，不走该分支。不要为应用修复改写世界沙盒或全局优化设置。

当前原生普通家具getter上限100，因此本模组为自己的四种建筑精灵提供限定容量桥接，覆盖正常单人UI拖放、批量转移及Java队列Lua入口。仍保留原生收纳许可和重量边界；整理有方/杂乱无章按原版规则影响有效容量。其他模组如绕过Lua、直接从Java查询/限制容量，仍可能看到原生100上限，这类自定义自动存取需要单独适配；没有修改JAR、全局容量上限或使用注入器。

**时间边界**：只对当前单人会话中连续观察到的、已加载且通电的时间返鲜。离区、离线、停用模组及单次超过15游戏分钟的异常时钟跳变不补返鲜。首次重新认领先调用原生补龄，避免误抹普通腐坏时间。不会用返回时“现在有电”推断整个离区期间有电。

## 搬运与停用

采用原生搬运，先清空冰箱；搬运物品保留各台开关与标识。搬运期间不返鲜。重新放置后按当前沙盒容量恢复。拆除遵循原生家具流程，没有额外钟表返还，避免复制材料。

移除模组前请清空并拆除该自定义建筑，正常保存退出。候选版不可将停用后的缺失贴图/建筑表现当作已验证的自动回退；恢复时应使用同一候选包。本次仅备份被修改的存档启用名单，未新建完整世界进度备份；名单备份不构成完整存档。
